# دیجی‌کارن

یک وب‌اپ فروشگاه نمونهٔ فارسی و راست‌به‌چپ با React، Vite و یک سرور اختیاری Node.js. هویت بصری آبی از لوگو، آیکون و بنر ارسالی کاربر استفاده می‌کند و تصاویر قبلی فروشگاه نیز حفظ شده‌اند.

## اجرا

به Node.js نسخهٔ ۲۲٫۱۳ یا جدیدتر نیاز است؛ `node:sqlite` در این نسخه‌ها هنوز ممکن است هشدار experimental نمایش دهد.

```bash
npm install
npm run dev
```

فروشگاه توسعه به‌طور پیش‌فرض روی پورت ۵۱۷۳ اجرا می‌شود. برای اجرای نسخهٔ ساخته‌شده:

```bash
npm run build
npm start
```

سرور نسخهٔ ساخته‌شده به‌طور پیش‌فرض از پورت ۳۰۰۰ استفاده می‌کند؛ با متغیر محیطی `PORT` قابل تغییر است. `npm run preview` نیز همان سرور نسخهٔ ساخته‌شده را اجرا می‌کند. برای آزمون‌ها از `npm test` استفاده کنید.

## امکانات نمونه

- صفحهٔ اصلی فروشگاهی با بنرهای قابل تعویض، بخش تازه‌های فروشگاه و طراحی واکنش‌گرا
- ۲۳ دستهٔ اصلی، ۹۸ زیردستهٔ قابل پیمایش و ۱۰۰ کالای نمونه؛ هر زیردسته کالاهای مرتبط خود را نمایش می‌دهد و از منو، فهرست قابل جست‌وجوی دسته‌ها و صفحهٔ دسته قابل دسترسی است. دسته‌های خواب و حمام، روشنایی، لوازم اداری، جشن و نظافت همراه دسته‌های قبلی در صفحهٔ اصلی معرفی شده‌اند.
- هر کالا صفحهٔ اختصاصی قابل‌اشتراک با مسیر نمونهٔ `?product=pet-care-kit`، بزرگ‌نمایی تصویر، مشخصات، انتخاب تعداد، وضعیت موجودی و کالاهای مرتبط دارد. نمایش سریع همچنان از آیکون چشم روی کارت در دسترس است؛ پیشنهادها بر اساس دسته و زیردسته‌اند، نه توصیه‌گر شخصی‌سازی‌شده.
- جست‌وجوی چندواژه‌ای فارسی/عربی، مرتب‌سازی، فیلتر حداقل درصد تخفیف و محدودهٔ قیمت با ارقام فارسی یا لاتین، و فیلتر واکنش‌گرا برای موبایل. مرتب‌سازی و فیلترها در پیوند صفحه باقی می‌مانند؛ فیلتر موجودی فقط هنگام اتصال به موجودی آزمایشی سرور اعمال می‌شود.
- مقایسهٔ حداکثر چهار کالا کنار یکدیگر، افزودن کالا از کارت یا صفحهٔ محصول، و ساخت پیوند قابل‌اشتراک مقایسه. شناسهٔ کالاهای انتخاب‌شده داخل پیوند اشتراک قرار می‌گیرد؛ انتخاب محلی با باز کردن پیوند دیگران بی‌صدا بازنویسی نمی‌شود.
- «فضای خرید من» با دسترسی از سربرگ، سبد، علاقه‌مندی‌ها، مقایسه، بازدیدهای اخیر، یادداشت‌ها و رسیدها را یک‌جا نشان می‌دهد. هر گروه را می‌توان پس از تأیید جداگانه پاک کرد و شهر را به مقدار پیش‌فرض بازگرداند. انتقال کالا از سبد به علاقه‌مندی‌ها و حذف تکی از تاریخچه نیز در دسترس است.
- برای هر کالا می‌توان یک یادداشت شخصی ثبت یا ویرایش کرد؛ حداکثر ۵۰ یادداشت و هر کدام تا ۵۰۰ نویسه. یادداشت‌ها دیدگاه عمومی نیستند، اما رمزگذاری یا با حساب کاربری محافظت نمی‌شوند: هر کسی به مرورگر دسترسی داشته باشد می‌تواند آن‌ها را ببیند، پس اطلاعات حساس وارد نکنید.
- پس از ثبت موفق سفارش در نسخهٔ سروری، در صورت امکان خلاصهٔ حداکثر ۲۰ رسید آزمایشی در مرورگر ذخیره می‌شود؛ این خلاصه نام، شماره موبایل، نشانی و کلید درخواست را نگه نمی‌دارد. حذف رسید مرورگر **رکورد سفارش را از پایگاه‌دادهٔ سرور حذف نمی‌کند** و این فهرست سامانهٔ پیگیری واقعی نیست.
- مرکز راهنمای قابل جست‌وجو، اطلاعات روشن دربارهٔ نسخهٔ نمایشی، حریم خصوصی و محدودیت‌های پرداخت، ارسال، بازگشت و پشتیبانی را نمایش می‌دهد؛ دکمهٔ راهنمای شناور فقط پاسخ‌های خودکار دارد و به پشتیبان انسانی متصل نیست.
- کاتالوگ و موجودی **آزمایشی** از API خوانده می‌شوند. ثبت سفارش آزمایشی در SQLite ذخیره می‌شود، موجودی آزمایشی را کاهش می‌دهد و شمارهٔ پیگیری آزمایشی برمی‌گرداند. هر سفارش حداکثر ۳۰ نوع کالا و از هر کالا حداکثر ۱۰ عدد دارد.
- قیمت و موجودی هنگام ثبت مجدداً در سرور بررسی می‌شوند؛ عملیات ذخیره و کاهش موجودی اتمی است و تکرار همان درخواست با کلید یکسان، سفارش دیگری ایجاد نمی‌کند.
- وب‌اپ شامل مانیفست، آیکون‌های برگرفته از آیکون ارسالی و service worker است. پس از اولین بازدید و دریافت کامل فایل‌های عمومی، مرور کاتالوگ و صفحات کالا بدون اینترنت هم ممکن است؛ نصب به پشتیبانی و انتخاب کاربر در مرورگر بستگی دارد. درخواست‌های API و اطلاعات فرم کش نمی‌شوند.
- لوگوی افقی در `public/digikaren-logo.png`، آیکون مرورگر در `public/favicon.png` و تصاویر اصلی ارسالی در `public/brand/` قرار دارند. فایل‌های SVG مسیرهای قبلی، تصویر PNG را در خود دارند و برداری نیستند.

**محدودیت مهم:** این پروژه هنوز یک نمونه است و به کد یا سرویس‌های دیجی‌کالا متصل نیست. کالاها، قیمت‌ها، موجودی، تخفیف، امتیاز، تعداد نظر و فروش و زمان‌سنج نمونه‌اند. سفارش آزمایشی به معنی خرید واقعی نیست و هیچ پرداخت، ارسال، پیامک، احراز هویت، خبرنامه یا پشتیبانی واقعی انجام نمی‌شود. در فرم آزمایش فقط اطلاعات ساختگی وارد کنید؛ اطلاعات فرم در پایگاه‌داده ذخیره می‌شوند. برای استفادهٔ واقعی باید مدیریت و احراز هویت امن، پنل مدیریت، پرداخت، ارسال، امنیت، سیاست نگهداری داده و انطباق قانونی پیاده‌سازی و بررسی شوند.

## نسخهٔ ایستای GitHub Pages

نشانی پروژه: [https://rahmaniho.github.io/Digikaren/](https://rahmaniho.github.io/Digikaren/). GitHub Pages فقط فایل ایستا ارائه می‌کند و سرور Express یا SQLite را اجرا نمی‌کند؛ بنابراین در این نسخه کاتالوگ، قیمت‌ها و تصاویر نمونه‌اند، موجودی واقعی مشخص نیست، سبد، علاقه‌مندی‌ها، مقایسه، بازدیدهای اخیر و یادداشت‌ها فقط در مرورگر ذخیره می‌شوند و **ثبت سفارش، ورود، پرداخت و ارسال فعال نیستند**. فرم سفارش یا شماره موبایل در نسخهٔ ایستا نمایش داده نمی‌شود. این نسخه و نسخهٔ سروری به یکدیگر متصل نیستند.

انتشار با GitHub Actions و فایل `.github/workflows/pages.yml` انجام می‌شود: پس از هر push یا ادغام در `main`، آزمون‌ها اجرا می‌شوند، نسخهٔ ایستا با مبنای `/Digikaren/` ساخته می‌شود و در محیط `github-pages` منتشر می‌گردد. تنظیم منبع Pages باید روی **GitHub Actions** باشد. فایل‌های خروجی در مخزن نگهداری نمی‌شوند.

برای ساخت محلی همان نسخهٔ ایستا:

```bash
npm ci
npm run build:pages
```

خروجی در `dist/` ساخته می‌شود و باید از زیرمسیر `/Digikaren/` ارائه شود. برای بازگشت به نسخهٔ سروری، دوباره `npm run build` و سپس `npm start` را اجرا کنید؛ خروجی ایستای Pages با خروجی سروری جایگزین می‌شود.

وب‌اپ از روی HTTPS یا localhost قابل نصب است. در مرورگرهای پشتیبانی‌شده از دکمهٔ نصب استفاده کنید؛ در Safari آیفون از Share و سپس Add to Home Screen استفاده کنید. حالت آفلاین پس از نصب موفق service worker و دریافت کامل فایل‌های کاتالوگ در دسترس است؛ صفحات فضای من و راهنما نیز با داده‌های محلی در دسترس‌اند. در حالت سروری، موجودی زنده و ثبت سفارش به اتصال و سرور نیاز دارند. فایل‌های کش صرفاً عمومی‌اند و دادهٔ API یا سفارش را در بر نمی‌گیرند. پاک‌سازی هر گروه در فضای من حافظهٔ آفلاین، دیگر داده‌های سایت یا پایگاه‌دادهٔ سرور را پاک نمی‌کند؛ برای حذف کامل داده‌های محلی از تنظیمات مرورگر استفاده کنید.

## داده و API آزمایشی

پایگاه‌دادهٔ SQLite به‌صورت خودکار در `var/digikaren.sqlite` ساخته می‌شود و در Git قرار نمی‌گیرد. مسیر آن را می‌توان با `DIGIKAREN_DB` تغییر داد؛ برای استقرار باید روی فضای ذخیره‌سازی پایدار و خصوصی قرار گیرد. فهرست خلاصهٔ حداکثر ۱۰۰ سفارش آزمایشی، بدون نمایش مشخصات تماس، با `npm run orders` قابل مشاهده است. فعلاً پنل مدیریت یا API عمومی برای خواندن سفارش‌ها وجود ندارد.

- `GET /api/catalog` کاتالوگ و موجودی نمونه را برمی‌گرداند.
- `GET /api/categories` دسته‌ها، زیردسته‌ها و تعداد کالاهای نمونه در هر بخش را برمی‌گرداند.
- `POST /api/demo-orders` سفارش **آزمایشی** را با بدنهٔ JSON و سرآیند `Idempotency-Key` ثبت می‌کند. سرور شناسه‌ها، تعداد، قیمت مورد انتظار، موجودی و مشخصات نمونه را اعتبارسنجی می‌کند؛ مبلغ را از کاتالوگ خودش محاسبه می‌کند.
- `GET /api/health` وضعیت سرور نمونه را نشان می‌دهد.

پایگاه‌داده حاوی ورودی‌های فرم است؛ فایل و نسخه‌های پشتیبان آن را عمومی نکنید. محدودکنندهٔ درخواست فعلی صرفاً برای محیط آزمایشی است و جایگزین کنترل‌های عملیاتی، احراز هویت یا حفاظت داده برای فروشگاه واقعی نیست.

### افزودن کالای نمونه

دسته‌ها و زیردسته‌ها در `src/data.js` و کالاهای نمونهٔ اضافه‌شده در `src/extra-products.js`، `src/more-products.js` و `src/new-products.js` تعریف شده‌اند. برای هر کالا شناسهٔ یکتا، مسیر تصویر، قیمت نمونه، `categories` و شناسه‌های متناظر در `subcategories` مشخص کنید و سپس سرور را دوباره اجرا کنید. کالای جدید با موجودی آزمایشی اولیه به پایگاه‌داده اضافه می‌شود؛ هنگام اجرا فقط اطلاعات دسته‌بندی کالاهای قبلی همگام می‌شوند و موجودی، سفارش‌ها و قیمت‌های ذخیره‌شده بازنویسی نمی‌شوند. تغییرات سایر مشخصات کالاهای موجود در فایل منبع، تا زمانی که مدیریت کالا به پروژه اضافه نشود، به‌صورت خودکار قیمت یا اطلاعات قبلی پایگاه‌داده را تغییر نمی‌دهد. آزمون `npm test` درستی دسته‌بندی‌ها و مسیر تصاویر را بررسی می‌کند.
